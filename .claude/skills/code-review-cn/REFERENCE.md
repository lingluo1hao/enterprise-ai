# 代码审查安全规则（详细）

在 SKILL.md 主清单基础上，补充以下更细的安全检查点。

## 密钥与凭据
- 扫描硬编码 IP / 密码 / API Key / token，重点文件：`.env*`、`settings.*`、`config.*`、`init_db.sql`。
- 仓库内不应提交任何真实密钥；默认密码 / dev-profile 凭据必须有明确迁移路径。
- 密钥正则（命中即报告）：
  - AWS Access Key：`AKIA[0-9A-Z]{16}`
  - OpenAI/常见 sk- 密钥：`sk-[a-zA-Z0-9]{32}`
  - GitHub Token：`ghp_[A-Za-z0-9]{36}`
- 误报兜底：命中正则但位于测试夹具 / 文档示例 / 模板占位符（如 `YOUR_API_KEY`、`xxxxx`）时，标记为「低危：疑似示例」而非密钥泄漏。

## 注入与执行
- 命令执行（os.system / subprocess / eval / exec / shell=True）的输入来源是否受控。
- 危险函数：`eval` / `exec` / `os.system` / `subprocess` 直接拼接用户输入即为高危。
- SQL 拼串是否改用参数化查询；文件路径拼接是否存在路径穿越（`../`、绝对路径拼接）。
- 提示词注入：LLM 输入是否可能把用户内容当系统指令执行（RAG 文档内容被注入时尤其要查）。

## SSRF（服务端请求伪造）—— RAG 系统重点
- 任何对外请求（LLM / embedding / fetch / 抓取文档）的 URL 是否硬编码或白名单。
- 用户输入拼进 URL、或文档内容带可访问外链地址，即为 SSRF 高危。

## 认证与会话
- 会话 token 存储位置（httpOnly cookie？）是否可被脚本窃取；token 是否过期轮换。
- 登录是否有速率限制；是否存在默认弱口令（admin123 / password / 用户名=密码 类）。
- 越权（IDOR / 接口级鉴权缺失）：普通用户能否调用 admin 接口、查看他人数据。
- 鉴权失败是否 fail-closed（默认拒绝，而非默认放行）。

## 访问控制（多租户）
- 检索 / 查询是否带 tenant_id 下推；反馈 / 任务恢复是否校验用户归属。
- 数据物理隔离是否与逻辑隔离一致（同一个 tenant 过滤串能否被绕过）。

## 敏感数据与日志
- 密码是否明文存储 / 可逆加密；生产环境是否误开 debug 模式。
- 日志 / 报错回显是否泄露堆栈、SQL、密钥（把异常直接返回给前端）。

## 上传与文件
- 上传是否校验文件类型 / 大小；文件名是否清理（防路径穿越、覆盖）。
- 文件内容是否被当作可执行 / 可解析来源（解压、符号链接）。

## 数据一致性
- read-modify-write（先查后改/先删后插）是否原子或加锁；崩溃/并发是否丢数据。
- 错误处理是否静默吞异常（空 except / except: pass）。

## 资源与可用性
- 外部调用（LLM / 检索 / DB）是否有超时、重试上限，无死循环 / 无限重试。
- 高频接口是否限流；大输入是否截断（防 token / 内存 / 响应时间耗尽）。

## 依赖与供应链（A06）
- 是否存在已知漏洞的高危依赖版本（扫描 requirements / package-lock 常见 CVE）。
- 是否依赖来源不明的第三方包；锁文件是否缺失。

## 参考标准
- 安全基线详见 OWASP Top 10（2025），重点对照：A01 失效访问控制、A02 加密失败、A03 注入、A06 脆弱易受攻击的组件、A08 软件和数据完整性。
